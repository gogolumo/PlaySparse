# Game-aware storage: retained L0 result (2026-10-05)

Optional engine discovery now feeds deterministic offline profiles and packing
plans. It does **not** establish a compression improvement. Sampled raw selection
loses space and build CPU on these inputs. Original ZIP record boundaries improve
cross-version object reuse, with more metadata and analysis CPU. Generic defaults
and the runtime remain unchanged.

## Provenance and methodology

Generic baseline at sprint start (fetched main): `7783946b` (full identity in
[baseline provenance](raw/game-awareness-20261005/baseline-and-pilot-build/baseline-provenance.json)).
Implementation and final measurements: clean
`4952845f6546fd68f2951970c7ffd63fdf461829`; content digest and binary SHA-256 are in
[final build receipt](raw/game-awareness-20261005/quality-final/binary-build-manifest.json).
The initial baseline binary was preserved before implementation and its hash is
recorded in every run. Its local commit label/build log are retained; the initial
baseline has no signed attestation or full build receipt. Final candidates have
local receipts, also not signed attestations.

Universal-modder research: `0f5dcdfdcd8ed420f8413815bd6647586ab894a2`, MIT.
No dependency was installed, vendored or added to runtime. The actual optional
scanner was run from a read-only clone; its wrapper's implicit `uv` installation
was disabled with `UM_NO_UV=1`.

All final and pilot fixtures are L0 deterministic generated bytes (seed 505).
Primary v1: 16 deflated random 1 MiB ZIP entries, 8 MiB random data and scripts.
V2 inserts a ~349 KiB ZIP record and replaces 8 KiB inside another record.
The adverse corpus adds a 16 MiB mostly-zero file whose three exact 64 KiB probe
windows contain random bytes. This is intentionally unfavorable to sampling;
its complete original bytes are still reconstructed exactly.

Three repetitions per configuration, rotated execution order, identical v1/v2
input and query seed, 200 requests per random workload, 256 KiB chunk target,
Zstd level 3/raw fallback, 16 MiB userspace cache. Generic configurations use the
preserved main binary; candidate configurations use the new binary. All read
benchmarks use the same new binary. The preserved v1 reader verifies every
packed store. All requested query bytes and source identities match. No trial
is selected or omitted. Reports retain medians, population variance, min/max,
individual request-size distributions, every command and failure.

The tables show **medians of three trials**; latency cells are medians of each
trial's percentiles, not pooled percentiles. Cold disables the decompressed
userspace cache; OS/device caches are uncontrolled. Host performance is noisy.
CPU includes the whole child process, so candidate pack CPU includes profile
revalidation; inspect CPU is separately measured. Read CPU includes original
comparison reads, hashing, store opens and every benchmark phase. Physical
bytes sum store file lengths; allocated bytes use POSIX stat blocks including
directories. Metadata includes pack headers, unlike encoded object payloads.

The update budget sums v2 object payloads absent from v1 plus complete v2
manifest/index/commit metadata and one projected pack header. It is a
**hypothetical shared-CAS incremental byte budget**, not a published delta store,
actual update allocation, patch download size or existing update API. Full
independent v2 store sizes are shown separately.

A = generic CDC; B = CDC + explicitly opted-in `--experimental-skip-compression`;
C = CDC resets at validated original ZIP record boundaries and retains Zstd;
D = generic fixed 256 KiB. B is experimental and not recommended. A profile by
itself retains A's try-Zstd codec behavior. No engine label chooses a codec.

## Frontier interpretation

C saves **1,271,693 projected update bytes** relative to A on each corpus:
49.4622% primary and 45.9041% adverse. It reuses 1,273,780 more logical bytes.
Its encoded objects are 81 bytes smaller, while metadata grows 2,168 bytes,
so full store size grows **2,087 bytes**. Allocated size is unchanged on primary
and grows one 4 KiB block on adverse. This is an update-reuse tradeoff, not a
full-install compression gain.

C's inspect+pack CPU grows 0.027020 s (+39.3602%) primary and 0.043341 s
(+40.9391%) adverse. Cold p95 changes -0.037500 ms primary and +0.005375 ms
adverse; overlapping trial distributions and uncontrolled OS caches prevent a
stable read-latency improvement claim. The direct read path and cache policy
are unchanged.

On the declared observed dimensions **full physical size, inspect+pack CPU,
4 KiB cold p95, projected update bytes**, B is dominated by A on both final
corpora: every dimension is worse. This is not global dominance across every
counter: B has lower median RSS and primary warm p95. On the same dimensions,
A, C and D are non-dominated among these four configurations. C's smaller
update budget prevents A or D dominating it; A's full size is lower; D builds
and reads faster but has substantially worse update reuse. This is only an
observed L0 frontier and does not establish engine-label causality.

B's adverse full store grows **5,046,670 bytes (+19.6096%)** and update budget
by 3,998,144 bytes (+144.3204%). It avoids compression calls, but full identity
hashing, probes and plan validation outweigh that saving here. Byte integrity
still passes after false classification. B stays explicit opt-in rather than
becoming a default optimization.

## Retained earlier and negative runs

The clean `ae62a56` pilot combined ZIP boundaries **and** sampled raw in C.
After the sampling failure, C was changed to retain Zstd, and B became explicit
opt-in. Pilot and final results are separate, not selected competing trials.

[Primary pilot](raw/game-awareness-20261005/pilot-primary/evidence/result.json) and
[adverse pilot](raw/game-awareness-20261005/pilot-adverse/evidence/result.json) each retain all 12 runs.
Pilot B adverse physical bytes: 30,782,361 versus A's 25,735,691 (+5,046,670).
Pilot C primary update budget: 1,300,176 versus A's 2,571,038 (-1,270,862), with
+2,918 full-store bytes and +0.030671 s inspect+pack CPU. These early measurements
motivated the conservative final split; they are not discarded.

The initial Windows run failed because the profile used writable mode 0666
while the existing store maps it to 0644. The mapping was corrected in
`1309267`; [failed log](raw/game-awareness-20261005/initial-windows-failure.log) is retained. A later
review found compact metadata budgeting could emit pretty JSON over 16 MiB.
`4952845` bounds exact serialized sidecar bytes before output creation and tests
the UTF-8/newline boundary.

## Architecture, scope and reproduction

`inspect-game → GameProfile v1 → measured probes → PackingPlan v1 → pack → normal
v1 store`. Inputs and sidecars are bounded, paths safe, fields/versions strict;
pack recomputes source identity, measurements, codec decisions and ZIP boundaries
before creating destination parents. Streamed bytes/hash/mode are checked again
before publication. Generic defaults remain CDC 256 KiB/Zstd3/raw fallback.
The runtime has no profile, UM or Python dependency. Policy/RangeResolver/FUSE/
macFUSE/WinFsp and the v1 storage format are unchanged.

UM features used: optional `scan SOURCE --json`; normalized game/store/appid,
engine score/version/matched relative evidence, other engine signals,
executable model/architecture and anti-cheat labels; engine/container knowledge
used as research hints. Routes, loaders, save/Workshop locations, modding,
asset decoding, injection, bypasses, tool installation and knowledge refresh
were not integrated. Only a bounded structural ZIP reader is implemented;
other engine archive names are advisory. Attribution is in
[THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md).

For this **game-aware packing experiment**, L1 open workloads, L2 owned
installations, startup, launcher/DRM/anti-cheat compatibility, mounted performance
and physical-device I/O amplification remain NOT RUN/unknown. Separate project
reports now record [Mac Project Zomboid hybrid gameplay](macos-project-zomboid-2026-10-05.md)
and [physical Windows/Elden Ring validation](windows-physical-elden-ring-2026-10-05.md);
those do not validate the new game-aware plan or these generated-workload savings. No breakthrough/industry claim is made.
Runtime priors stay empty; actual traces remain authoritative. UM helps discovery,
but the measured reuse gain comes from original-byte container boundaries.

See [experiment commands](../../experiments/05-game-aware-packing/README.md),
[profile/plan contract](../game-awareness.md), [pre-code audit](../game-awareness-audit.md)
and [exact changed-file inventory](raw/game-awareness-20261005/files-changed.txt).
The raw collection preserves original bytes and Windows CRLF through scoped Git
attributes; whitespace checks apply to authored code/docs. It contains JSON/logs/traces/hashes, no fixture, game asset,
store, overlay data or executable payload. A SHA-256 inventory accompanies it.
